# FinatriX for Android — build, release and Play Store runbook

> **Release status lives in [MOBILE_RELEASE_READINESS.md](MOBILE_RELEASE_READINESS.md)**
> (last audited 2026-10-01). This file is the how-to; that one is the verified
> current state, blockers and remaining owner actions.

The Android app is the FinatriX web app packaged natively with
[Capacitor 8](https://capacitorjs.com). The same `dist/` the website ships is
bundled **inside the APK** — the app opens instantly and offline, and every
Play build is exactly the code that was tested. The consequence: **a web deploy
does not update the app.** Ship an app release whenever app-visible code changes.

| | |
|---|---|
| Package | `co.finatrix.app` (permanent — never change it) |
| Page origin in the app | `https://localhost` (permanent — changing it orphans on-device data) |
| Min / target SDK | Android 7.0 (API 24) / API 36 |
| Permissions | `INTERNET` only (plus `VIBRATE`, merged in by the haptics plugin) |
| Native project | `android/` — generated by Capacitor, then customised (see below) |

---

## 1. How the app layer works

**One bundle, two platforms.** `src/native/platform.ts` answers `isNativeApp()`
synchronously from the bridge Capacitor injects; it has no dependencies so it
costs the website nothing. Everything that talks to native code is in
`src/native/bridge.ts`, a lazy chunk (~13 KB) only the app ever downloads.

What the app does differently from the website:

| Area | Behaviour in the app | Where |
|---|---|---|
| Start screen | `/` → `/tools/dashboard` (no marketing landing page) | `App.tsx` |
| System BACK | Closes the top dialog/drawer/menu → walks history → backgrounds the app at a top-level screen | `bridge.ts` `onBack` |
| Edge to edge | Draws under the system bars; `--fx-safe-*` tokens pad headers, tab bar, sheets | `tokens.css`, `index.css` |
| System bars | Icon colour + backdrop follow the **in-app** theme, not just the OS | `bridge.ts` + `SystemUiPlugin.java` |
| Splash | Android 12 splash (mark on charcoal disc), held until the first screen paints | `bridge.ts`, `styles.xml` |
| Keyboard | Tab bar and floating buttons hide while typing | `html.fx-kb-open` in `index.css` |
| Haptics | Named haptic events route to Android's haptic engine | `lib/haptics.ts` |
| Font size | WebView text follows the system font-size setting (WCAG 1.4.4) | `MainActivity.java` |
| Google sign-in | Opens in a Chrome Custom Tab, returns via `co.finatrix.app://auth/callback` | `AuthContext.tsx`, `bridge.ts` |
| Email links | Confirmation/reset links point at `https://finatrix.co` (App Links bring them into the app) | `publicLinkOrigin()` |
| External links | Open in an in-app Custom Tab; `finatrix.co` links route to in-app screens | `bridge.ts` `onDocumentClick` |
| Purchases | **Not offered** (Play Billing policy). Existing Pro members keep access | `canPurchaseInApp()` |
| Web-only chrome | Breadcrumbs, Back pill, "Home" links hidden via `[data-web-only]` | `index.css` |
| Service worker | Not registered (assets already on device) | `main.tsx` |

## 2. One-time machine setup

```bash
brew install openjdk@21
```

Plus the Android SDK (Android Studio, or the command-line tools) with platform
36. `scripts/android-build.sh` finds JDK 21 on its own.

## 3. Everyday builds

```bash
npm run android:apk          # web build + sync + debug APK
npm run android:open         # open the native project in Android Studio
npm run android:assets       # regenerate icons/splash/store graphics from the brand art
```

Install the debug APK on a phone or emulator:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Debug builds are inspectable at `chrome://inspect`; release builds are not.

## 4. Before the FIRST release — backend changes that must ship

These are required for the app to work; none of them change the website's behaviour.

1. **Deploy the edge functions** (adds `https://localhost` to the CORS allowlist,
   the new `account-delete` function, and the `ai_answer_reported` event):
   ```bash
   npx supabase functions deploy careers-jobs careers-ai careers-email careers-billing-checkout account-delete --project-ref "$SUPABASE_PROJECT_REF"
   ```
   ```bash
   npx supabase functions deploy careers-billing-webhook analytics-collect --no-verify-jwt --project-ref "$SUPABASE_PROJECT_REF"
   ```
   Until this is done, analytics from the app are rejected by CORS (verified on
   the emulator) and in-app account deletion fails.
2. **Supabase → Authentication → URL Configuration → Redirect URLs**: add
   `co.finatrix.app://**`. Without it Google sign-in in the app returns to the
   website instead of the app.
3. **Deploy the website** (`npm run build && npx wrangler deploy`) — ships the
   updated privacy policy (Android, AI, analytics and account-deletion sections),
   the in-app account deletion UI, and the `/.well-known/assetlinks.json` route.
4. **App Links fingerprint** — after creating the app in Play Console (step 6),
   copy the **App signing key certificate SHA-256** from *Test and release → App
   integrity* and set it on the Worker, then redeploy:
   ```bash
   npx wrangler secret put ANDROID_CERT_SHA256
   ```
   Verify: `curl -s https://finatrix.co/.well-known/assetlinks.json` returns JSON
   with that fingerprint (and `https://www.finatrix.co/...` too — no redirect).
   Multiple fingerprints are comma-separated (e.g. add the upload key's to test
   App Links with a locally signed build).

## 5. Signing (once)

```bash
scripts/android-keystore.sh
```

Creates `android/finatrix-upload.jks` + `android/keystore.properties` (both
gitignored). This is the **upload key**; with Play App Signing, Google holds the
real signing key and can reset a lost upload key. Back up the `.jks` and its
password in a password manager anyway.

## 6. Releasing

```bash
npm run android:release -- 1 1.0.0      # versionCode, versionName
```

Output: `android/app/build/outputs/bundle/release/app-release.aab` (R8-minified,
~11 MB). `versionCode` must increase on every upload.

**Play Console (first time):**

1. *Create app* → name **FinatriX**, default language English (India or US),
   App, Free.
2. *Test and release → App integrity*: keep **Play App Signing** on (default).
3. *Internal testing* → create a release → upload the AAB → add yourself as a
   tester → install from the opt-in link and run the checklist in §8.
4. **Personal developer accounts created after Nov 2023 must run a closed test
   with at least 12 testers opted in for 14 continuous days** before production
   access is granted. Organisation accounts are exempt. Plan for this.
5. Complete *Grow → Store presence* (§7) and *Policy → App content* (§9).
6. Promote to production (staged rollout: start at 20%).

## 8. Pre-release device checklist

Run `npm run verify:native` before release to check the deployed backend CORS
rules and both platforms' association files. It is read-only and reports missing
release configuration separately from local build success.

Verified on an API 36 emulator (Pixel 8 profile) for this release; repeat on a
real phone before each production rollout:

- [ ] Cold start shows the splash, then the dashboard — no white flash, no title bar
- [ ] Status/navigation bar icons readable in dark AND light in-app theme (toggle both ways)
- [ ] Header pinned below the status bar while scrolling; tab bar clear of the gesture handle
- [ ] BACK: closes drawer → closes dialog → previous screen → backgrounds app at Dashboard
- [ ] Keyboard: tapping a field hides the tab bar and AI button; they return on close
- [ ] Google sign-in opens a Custom Tab and returns signed in (needs §4.2)
- [ ] Email/password sign-in, sign-out, cloud sync between app and website
- [ ] `adb shell am start -a android.intent.action.VIEW -d https://finatrix.co/tools/goals co.finatrix.app` opens Goals
- [ ] Profile → Delete account works end-to-end with a throwaway account (needs §4.1)
- [ ] System font size at Largest: text scales, nothing clipped
- [ ] Airplane mode: Budget, Expenses, Goals work with no connection
- [ ] No purchase buttons or prices anywhere (Careers billing, Pro paywall, /pricing redirects)

## 9. Policy → App content (answers)

**Privacy policy:** `https://finatrix.co/privacy`

**App access:** All functionality is available without an account (guest mode).
Signing in only adds cloud sync and FinatriX AI. No credentials needed for review.

**Ads:** No, the app contains no ads.

**Content rating:** Reference/educational finance tool. No violence, sexual
content, gambling, controlled substances or user-to-user communication. The AI
assistant is generative — answer the questionnaire's AI question *Yes* and note
that users can report any answer in-app.

**Target audience:** 18 and over.

**Financial features declaration:** Budgeting/expense tracking and educational
calculators. No loans, no investment execution, no money transfers, no crypto,
no banking services.

**Data safety** — derived from the code, keep it in sync with the privacy policy:

| Data type (Play category) | Collected | Shared | Optional | Purpose |
|---|---|---|---|---|
| Personal info → Email address | Yes (account) | No | Yes | Account management |
| Personal info → Name (display name) | Yes (if entered) | No | Yes | Account management |
| Financial info → Other financial info (budgets, expenses, goals you enter) | Yes, **only when signed in** (cloud sync) | No | Yes | App functionality |
| App activity → Other user-generated content (FinatriX AI questions) | Yes, when AI is used | No* | Yes | App functionality |
| Financial info → Purchase history (merchant descriptions from a statement import, sent for AI categorisation) | Yes, only signed in **and** after the user allows AI | No* | Yes | App functionality |
| App activity → App interactions | Yes (cookieless, per-visit, opt-out in Settings) | No | Yes | Analytics |
| App info & performance → Crash logs, Diagnostics | Yes | No | Yes | Analytics |

\* Sent to service providers (Supabase, OpenRouter and its model provider) that
process it on FinatriX's behalf — Play does not count processing by a service
provider as "sharing". Nothing goes to the AI provider until the user taps
"Allow" on an in-app consent prompt (`src/lib/ai/consent.ts`, enforced in the
transport); it can be withdrawn in Settings → Privacy.

- Data is encrypted in transit: **Yes** (HTTPS only; cleartext disabled).
- Users can request deletion: **Yes** — in-app (Profile → Delete account) and
  at `https://finatrix.co/privacy#delete-account` (**enter this as the account
  deletion URL**).
- Guest data never leaves the device.

**Payments:** The app sells nothing. Careers Pro is sold only on the website;
the app neither shows prices nor links to the checkout (Payments policy /
anti-steering). If in-app purchase is ever wanted, integrate Play Billing
behind `canPurchaseInApp()`.

## 10. Native project customisations (keep when regenerating)

If `android/` is ever regenerated with `npx cap add android`, re-apply:

- `AndroidManifest.xml` — App Links + OAuth intent filters, `adjustResize`, no cleartext
- `MainActivity.java` — edge-to-edge after `super.onCreate`, font scale, WebView background
- `SystemUiPlugin.java` — window colour behind the bars
- `res/values*/colors.xml`, `styles.xml`, `drawable/splash.xml`, `mipmap-*` (run `npm run android:assets`)
- `app/build.gradle` — signing from `keystore.properties`, R8, versioning, asset exclusions
- `.gitignore` — keystores
